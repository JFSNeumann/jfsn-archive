## Technical Hazards — corrects the inventory's "not yet assessed in detail" status

The inventory flagged this record as needing the same close review already given to `site002`/`site003`. That review is now complete, and it found a live hazard:

- **Four complete, functioning PHP form handlers**, `scripts/form-u643.php`, `form-u1240.php`, `form-u1841.php`, `form-u2361.php` — **unlike `site003`, all three required helper files (`form_check.php`, `form_process.php`, `form_throttle.php`) are present and intact.** These are not dependency-broken; if PHP is active on whatever eventually serves a sanitized copy, they would genuinely execute `mail()` on a POST request. Two are subject-lined "A-Master Form Submission," two "Notify-Master Form Submission" (confirming the orphaned Notify page, see Technologies).
- **None of the three HTML pages in this folder (`index.html`, `phone/index.html`, `tablet/index.html`) contain a `<form>` tag or reference any of these four handler IDs directly** — checked by direct grep, zero matches in all three. These handlers are orphaned from whatever page(s) originally used them (most likely the missing "Notify"/"A-Master" pages), the same pattern as `site003`, but with a materially higher practical risk since the code would actually run.
- **All four handlers' `'email'` configuration is the literal placeholder `'from' => 'x@x.com', 'to' => 'x@x.com'`** — not Jeff's real email, unlike the working handlers found on `site002`/`site003`. This means the destination is inert, but the endpoint itself is not: a reachable PHP script that calls `mail()` on request is a hazard in its own right (a potential spam-relay vector) independent of where the mail would notionally go. Sanitization should remove these files regardless of the placeholder destination.
- **All four handlers' form fields are "Email" / "Password" / "Email"** — this reads as a login/signup form for a client app demo (consistent with the Notify-app screen images already in `images/`, e.g. `1-page_login 3_page 1.jpg`, `android1.png`), not a real contact form. Recorded as observation; not confirmed by anything beyond the field labels themselves.
- **External CDN fallback:** `musecdn2.businesscatalyst.com` (see Technologies) — same category as `site002`'s existing finding.
- An `http://invis.io/5Z1UVSZYM` link in `phone/index.html` — an InVision prototype-sharing short link, almost certainly dead today (InVision's public prototype-sharing product was discontinued). Link rot, not a security risk.

**No hazard found regarding:** Flash content (none present); analytics/tracking scripts of the New Relic/Google-Analytics kind (none found).
